## Конспект

**Рабочая среда для практики**

Примеры разбирались в VS Code, подключённом к виртуальной машине по SSH: в одном окне доступны и терминал, и файлы удалённой машины, поэтому файлы удобно копировать, редактировать и собирать в отчёт. Подключение выполняется под обычным пользователем, так как удалённый вход под root по умолчанию отключён из соображений безопасности; root-оболочку получают командой `su -` или через `sudo`. Настройка входа по ключам и ограничений доступа — тема третьей лабораторной работы.

**Переменные Bash**

Все переменные в Bash — строки; будет ли значение числом, определяется контекстом операции. Присваивание записывается без пробелов вокруг `=`, например `VAR="value"`, обращение — `$VAR` или `${VAR}`. Результат команды помещается в переменную через `MYVAR=$(whoami)` (внутри скобок допустимы ключи и конвейеры), целочисленная арифметика выполняется через `A=$((5 + 5))`; дробных чисел Bash не поддерживает. Переменная хранится в памяти процесса bash и исчезает вместе с сессией.

```bash
name="Пётр"
echo $name1                # пусто: ищется переменная name1
echo ${name}1              # Пётр1: конкатенация строк
echo ${surname:-Романов}   # значение по умолчанию, если переменная не задана
```

Фигурные скобки показывают, где заканчивается имя переменной, а форма `${var:-значение}` подставляет значение по умолчанию. Другие варианты использования фигурных скобок предлагается изучить самостоятельно.

**Специальные переменные**

`$0`, `$1`, `$2`, …, `${10}` содержат имя скрипта и позиционные аргументы; если аргумент не передан, переменная пуста и ошибки не возникает. `$PWD` хранит рабочий каталог (`pwd -P` показывает физический путь, подробнее — на лекции о файловой системе), `$SECONDS` — время работы скрипта. Переменные `$UID`, `$EUID`, `$GROUPS`, `$HOME`, `$HOSTNAME`, `$HOSTTYPE`, `$OSTYPE`, `$PATH`, `$PPID` описывают пользователя, систему и окружение и пригодятся начиная с третьей лабораторной. `$*` и `$@` содержат все аргументы скрипта, `$!` — PID последнего фонового процесса, `$$` — PID самого скрипта.

```bash
#!/bin/bash
echo "Пользователь $1 и $2, третий аргумент: '$3'"
# ./script.sh great lazy  ->  третий аргумент пуст
```

**Условный оператор if и оператор case**

```bash
variable=5
if [ "$variable" -eq 10 ]; then
  echo "Variable is 10"
else
  echo "Variable is not 10"
fi
```

Пробелы после `[` и перед `]` обязательны, поскольку `[` — это команда. Без них Bash сообщает, что команда не найдена, но продолжает выполнять скрипт, поэтому писать на Bash нужно внимательно. Числа сравниваются операторами `-eq`, `-ne`, `-lt`, `-le`, `-gt`, `-ge`; строки — через `=`, `!=`, `<`, `>`, а проверки `-z` (пусто) и `-n` (не пусто) используются для пустоты строки. Оператор `case` заменяет цепочку вложенных `if` при проверке одной переменной на набор значений, ветка `*)` срабатывает по умолчанию; он удобен для меню запуска программ во второй лабораторной.

```bash
case $1 in
  5)  echo "five" ;;
  34) echo "no" ;;
  *)  echo "default" ;;
esac
```

**Циклы**

Цикл `for i in 1 2 3; do ... done` перебирает любой список: числа, строки или результаты команд. Числовой список создаёт `seq`: команда `seq 200 -2 100` выводит числа от 200 до 100 с шагом −2, обе границы включаются. Ключи `seq` — `-w` (выравнивание ведущими нулями), `-s` (свой разделитель), `-f` (формат) — удобны для генерации имён файлов. Возможен и цикл в стиле C, `for ((i=0; i<10; i++))`, а цикл `while [ "$count" -lt 5 ]; do ... ((count++)); done` выполняется, пока истинно условие.

**Функции**

Функция — именованный фрагмент кода, который можно вызвать из любого места скрипта. Параметры передаются через пробел, как скрипту, и читаются внутри функции как `$1`, `$2`. Это не классы: класс — шаблон объекта, а функция — просто блок кода; круглые скобки в объявлении отличают её от остальных конструкций, и параметры в них не указываются.

```bash
greet() {
  local name=$1
  local age=$2
  echo "Привет, $name! Вам $age лет."
}
greet "Алексей" 25
```

**Ввод с клавиатуры, tail, head и tee**

Команда `read -p "Введите: " var` ждёт ввода до нажатия Enter, а ключ `-t` задаёт тайм-аут в секундах. `tail -n 5 file` выводит пять последних строк, а `tail -f file` непрерывно следит за файлом: новые строки появляются в терминале сразу после записи. Это пригодится при отладке приложения, которое пишет текстовый лог и падает, а системы мониторинга вроде Grafana нет, — лог выводят в отдельном терминале. `head -n 5 file` показывает начало файла, что удобно для многогигабайтного CSV-датасета, который текстовый редактор не откроет. Утилита `tee` раздваивает вывод: она показывает его на экране и одновременно пишет в файл, например `ls -la | tee out.txt`.

**Конвейеры и перенаправление потоков**

Конвейер (пайп, `|`) передаёт текстовый вывод одной команды на вход следующей; последовательная обработка данных цепочкой утилит — главная сила Bash. Символы `>` и `>>` записывают вывод в файл с перезаписью и дописыванием соответственно, `<` подаёт файл на вход команды. У каждой программы есть три потока: stdin (0) — ввод, stdout (1) — вывод на консоль, stderr (2) — ошибки.

| Конструкция | Действие |
| ----- | ----- |
| `команда 2> error.log` | Ошибки уходят в отдельный файл, на консоль не выводятся |
| `команда > out.log 2>&1` | Вывод и ошибки собираются в одном файле |
| `команда 2> /dev/null` | Ошибки подавляются; самый частый приём |
| `команда > /dev/null 2>&1` | На экран не выводится ничего |

На примере каталога `/` показано: без перенаправления ошибок список выводится вместе с сообщениями об ошибках, с `2> /dev/null` остаётся только список, а с `> /dev/null 2>&1` экран пуст.

**Специальные файлы устройств**

Такие файлы видны в файловой системе, но реально на диске не существуют: их создаёт ядро Linux. `/dev/null` — «чёрная дыра», всё записанное в неё исчезает. `/dev/random` и `/dev/urandom` — источники случайных байтов, например `head -c 16 /dev/random | base64`; на лекции было сказано, что `random` надёжнее, а `urandom` быстрее. `/dev/zero` — бесконечный источник нулевых байтов: `head -c 100M /dev/zero > largefile` создаёт файл на 100 мегабайт, что на виртуальной машине с одним ядром занимает заметное время.

**Обработка текста: grep, sed, cut**

`grep` ищет строки по образцу, и в Linux образец может быть регулярным выражением — шаблоном строки; например, `fail(ed|ure)?` подходит под несколько вариантов слова. `sed` — потоковый текстовый процессор, который меняет строки на лету: `s/old/new/` заменяет первое вхождение, флаг `g` — все вхождения, можно делать резервную копию файла, выполнять несколько замен и удалять строки по шаблону. В заданиях `sed` понадобится, чтобы привести отчёт в порядок, а не прикладывать сырой вывод команд. Утилита `cut -d',' -f1` выбирает поле по разделителю.

Для самостоятельного разбора оставлен «ребус»: `tail -n +5 logfile.txt | sed -n '/ERROR/,/END/p' | head -10`. Начинать читать конвейер стоит с конца: `head -10` ограничивает вывод десятью строками, `sed -n '/ERROR/,/END/p'` печатает диапазон от первой строки с первым образцом до строки со вторым, а `tail` готовит входные данные из файла. Эквивалент на Python занял бы порядка двадцати строк.

**Bash и Python: границы применимости**

Для сравнения решалась задача: найти пять IP-адресов с наибольшим числом неудачных попыток входа по SSH в файле `auth.log`. На Bash это один конвейер:

```bash
grep "Failed password" /var/log/auth.log | awk '{print $(NF-3)}' | sort | uniq -c | sort -nr | head -5
```

`grep` оставляет строки с неудачными входами, `awk` выделяет поле с IP-адресом, `sort` выстраивает одинаковые адреса подряд (это необходимо, так как `uniq` считает только соседние строки), `uniq -c` выводит число вхождений и адрес, второй `sort -nr` сортирует по убыванию, `head -5` берёт первые пять строк. На Python решение использует модуль `re`, класс `Counter` и метод `most_common`; оно длиннее, но проще расширяется.

| Критерий | Bash | Python |
| ----- | ----- | ----- |
| Тип задачи | Стандартные операции с текстом, файлами и процессами через готовые утилиты | Сложная логика, циклы и ветвления над данными |
| Вычисления | Только целочисленные; для сложной математики — калькулятор `bc` | Любые |
| Форматы данных | Простой текст; JSON, XML возможны через `jq`, но тяжело | JSON, XML и другие сложные форматы |
| Внешние системы | HTTP через `curl` и базы данных возможны, но неудобны | HTTP API, базы данных |
| Параллелизм и отладка | Построчное выполнение, параллелизм неудобен, отладка сложнее | Параллельные алгоритмы, отладка проще |
| Окружение | Есть везде: встроенные устройства, минимальные системы, legacy-проекты | Нужен интерпретатор и экосистема |
| Объём скрипта | До примерно 30 строк | Больше 30 строк |

Bash хорош для диагностики, быстрых починок, мелкой автоматизации и скриптов-обёрток для систем управления кодом; навык работы с пайпами в любом случае необходим. Старые Bash-скрипты можно переписывать на Python с помощью языковых моделей, если не требуется менять бизнес-логику.

**Ключевой вывод лекции**

В Linux существует несколько способов взаимодействия с системой (CLI, графические среды, инфраструктура как код — Ansible и Terraform), а эффективная работа в командной строке опирается на историю команд, автодополнение и справку. Главная сила Bash — длинные пайплайны, где текстовый вывод одной команды становится входом другой. Для сложной обработки данных и взаимодействия с внешними сервисами нужен Python, но Bash остаётся универсальным «швейцарским ножом», который всегда под рукой.

### Уточнения к лекции

В нескольких местах я упростил или неточно сформулировал детали, а на одном слайде есть неточность. Давайте разберём их отдельно.

* **Переменные `$-` и `$#`.** На слайде количество параметров приписано `$-`. Корректно так: число аргументов хранит `$#`, а `$-` содержит текущие флаги оболочки (на лекции получилось `himBH`).
* **`$*` и `$@`.** Я описал их различие упрощённо. Точнее, в кавычках `"$*"` склеивает аргументы в одну строку, а `"$@"` сохраняет каждый как отдельное слово, поэтому в скриптах чаще используют `"$@"`.
* **Скорость `for` и `seq`.** Я сказал, что цикл по готовому списку быстрее C-подобного. Точнее: `seq` — внешняя утилита, и на небольших диапазонах разница незаметна, а на больших обычно выигрывает `{1..N}` или цикл в стиле C.
* **`tail -n +5` и `head -10`.** `tail -n 5` выводит последние пять строк, а `tail -n +5` выводит всё, начиная с пятой строки файла. `head -10` берёт первые десять строк, отсчёт идёт сверху вниз. Знак `+` у `tail` меняет направление отсчёта на «с N-й строки», поэтому эти формы дают разный результат в «ребусе».
* **`/dev/random` и `/dev/urandom`.** Я противопоставил надёжность и скорость. В современных ядрах Linux (с версии 5.6) разница практически стёрлась, и `/dev/urandom` подходит для большинства задач, включая криптографические.
* **Размер `100M`.** Суффикс `M` в `head -c` означает 100 МиБ (104 857 600 байт); ровно 100 000 000 байт даёт `100MB`. Содержимое файла из `/dev/zero` — нулевые байты, а не символ «0».
* **`awk '{print $(NF-3)}'`.** `NF` — число полей в строке, поэтому выражение выбирает четвёртое поле с конца; в строках лога SSH это IP-адрес. Я назвал его «третьим полем».
* **Ошибки в скриптах.** Я упомянул, что Bash продолжает работу после ошибки; добавлю, что остановку при первой ошибке включает `set -e`.
* **`ps -A`.** Команда показывает все процессы и без прав root; права root нужны для действий над чужими процессами.

### Ключевые понятия

#### Оболочка и синтаксис Bash

| Термин                       | Определение для словаря                                                                   |
| ---------------------------- | ----------------------------------------------------------------------------------------- |
| CLI (Command Line Interface) | Интерфейс командной строки — основное средство управления Linux через текстовый терминал. |
| Шелл (shell)                 | Командная оболочка, запускаемая при входе пользователя в систему.                         |
| Bash                         | Командный интерпретатор GNU, основной шелл большинства дистрибутивов Linux.               |
| Шебанг (`#!/bin/bash`)       | Первая строка скрипта, указывающая интерпретатор для его выполнения.                      |
| Переменная Bash              | Именованная область памяти процесса bash; все значения хранятся как строки.               |
| Подстановка команды `$(...)` | Конструкция, помещающая вывод команды в переменную или строку.                            |
| Арифметика `$((...))`        | Целочисленные вычисления в Bash.                                                          |
| `${var:-default}`            | Подстановка значения по умолчанию для незаданной переменной.                              |
| Позиционные параметры        | Аргументы скрипта или функции: `$1`, `$2`, …, `${10}`.                                    |
| Оператор `case`              | Конструкция выбора по набору значений одной переменной.                                   |
| Функция                      | Именованный фрагмент кода, вызываемый с параметрами `$1`, `$2`.                           |

#### Потоки и перенаправление

| Термин | Определение для словаря |
| ----- | ----- |
| Пайп (конвейер) | Символ `|`: передача вывода одной команды на вход другой. |
| stdin / stdout / stderr | Стандартные потоки ввода, вывода и ошибок с номерами 0, 1, 2. |
| `>`, `>>`, `<` | Перенаправление: запись с перезаписью, дописывание в конец, подача файла на вход. |
| `2>&1` | Направление потока ошибок в стандартный вывод. |
| `/dev/null` | Специальный файл-«чёрная дыра», поглощающий всё записанное. |
| `/dev/zero`, `/dev/urandom` | Специальные файлы — источники нулевых и случайных байтов. |

#### Утилиты обработки текста

| Термин | Определение для словаря |
| ----- | ----- |
| `grep` | Поиск строк по образцу или регулярному выражению. |
| Регулярное выражение | Шаблон строки для поиска и замены текста. |
| `sed` | Потоковый текстовый процессор для замены, удаления и фильтрации строк. |
| `awk` | Текстовый процессор; в примере лекции выделяет поле строки. |
| `cut` | Вырезание полей по разделителю. |
| `sort`, `uniq -c` | Сортировка строк и подсчёт соседних одинаковых строк. |
| `head`, `tail`, `tail -f` | Вывод начала и конца файла; слежение за дописыванием файла. |
| `tee` | Раздвоение вывода: на экран и в файл. |
| `seq` | Генерация числовых последовательностей. |
