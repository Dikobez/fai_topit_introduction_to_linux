## Конспект

**Три группы пользовательских интерфейсов Linux**

В отличие от Windows, где графическая подсистема — неотъемлемая часть ОС, в Linux она опциональна: ядро можно эксплуатировать без графики вовсе (сервера, встраиваемые устройства, роботы-пылесосы). Выделяются три группы интерфейсных сред: текстовые (CLI-терминал и TUI-утилиты с псевдографикой), графические (подсистемы X11/Wayland + окружения рабочего стола поверх них) и сервисы удалённого/массового управления (веб-панели типа Cockpit, IaC-системы типа Ansible). Основной сценарий использования Linux — серверный, поэтому именно текстовый интерфейс остаётся главным инструментом инженера.

**TUI-утилиты как компромисс**

TUI (Terminal User Interface) — приложения, работающие в текстовом режиме, но рисующие псевдографические окна и поддерживающие интерактивное взаимодействие (пример — nmtui для настройки сети). Разработчики сертификационных программ (например, RHCSA) прямо рекомендают такие утилиты для быстрой настройки типовых задач — это не «несерьёзный» инструмент, а способ экономии времени. Как текстовые терминалы, так и TUI работают одинаково хорошо и локально (на физической консоли), и удалённо, через сетевые терминальные клиенты.

**Графические подсистемы: X11 и Wayland**

X11 (X.Org, стандарт с 1980-х годов, актуальная версия — X11) исторически создавался для распределённых сред: X-сервер работает на одной мощной машине, управляет отрисовкой окон (композитор, оконный менеджер, драйвер GPU), а приложение выступает клиентом и может отображаться на удалённом терминале при вычислениях на сервере. Главный недостаток X11 — безопасность: архитектура не изолирует окна друг от друга, и в классической реализации одно приложение потенциально может получить доступ к данным другого окна. Wayland (представлен в 2008 году) убирает эту многопользовательскую модель как редко нужную на практике: приложение само взаимодействует с ядром для рендеринга (используя аппаратное ускорение) и общается с композитором, который объединяет функции композитора и оконного менеджера; результат — изоляция окон друг от друга и более высокая производительность за счёт отказа от прозрачного сетевого проксирования.

**Окружения рабочего стола**

Выбор графического окружения (GNOME, KDE Plasma, Enlightenment, Cinnamon, MATE, XFCE/LXDE и др.) — вопрос вкуса и требований к ресурсам. Свежие версии GNOME работают только на Wayland; KDE и Enlightenment визуально насыщены, но требовательны к ресурсам; XFCE/LXDE — легковесные варианты для слабого железа (работают через X11, хотя на Wayland-системах доступен слой эмуляции XWayland для запуска X11-приложений).

**Сервисы удалённого управления и IaC**

Для управления одиночным сервером без постоянного набора команд подходят веб-панели вроде Cockpit — веб-приложение, дающее графическую консоль для просмотра логов, управления пользователями и сертификатами. При масштабе в десятки/сотни серверов эффективнее подход Infrastructure as Code: инфраструктура описывается декларативно (например, Ansible-плейбуки на YAML), и система автоматизации (Ansible и аналоги) применяет это описание к реальным серверам, разворачивая ПО и настройки по инструкции.

**Понятие шелла**

Шелл — программа, запускаемая автоматически при входе пользователя в систему и предоставляющая средства работы с ОС; в Windows аналог — процесс explorer.exe. В файле /etc/passwd для каждого пользователя указан путь к его шеллу (последнее поле строки); для интерактивных пользователей это обычно /bin/bash, а для служебных учётных записей — заглушка (например, /usr/sbin/nologin), не порождающая интерактивной сессии. Если вместо шелла указать путь к другой программе (например, текстовому редактору), пользователь при входе получит именно её, а не командную строку.

**Bash: программа, командная строка и интерпретатор одновременно**

Bash одновременно является: (1) обычным бинарным файлом в файловой системе (/bin/bash), который можно запустить повторно даже находясь внутри уже запущенного Bash, породив дерево процессов; (2) собственно командной строкой, которую видит пользователь; (3) интерпретатором языка команд и скриптов. Шебанг (#!/bin/bash или #!/bin/sh) в начале скрипта явно указывает, каким интерпретатором должен выполняться конкретный файл, независимо от того, какой шелл используется у пользователя по умолчанию. Bash — стандарт де-факто на подавляющем большинстве Linux-дистрибутивов, macOS (до перехода на Zsh) и BSD-систем; альтернативы (Zsh, Fish) предлагают более гибкую настройку (темы, плагины, хоткеи), но не являются столь же универсальными.

**Приглашение ввода**

Приглашение ввода (то, что заканчивается символами \$ или \#) показывает, что интерпретатор готов принимать команды в интерактивном режиме; между именем пользователя/хоста и символом приглашения обычно выводится текущий рабочий каталог. По умолчанию для root используется символ #, для обычных пользователей — $. Приглашение настраивается через переменную $PS1 и хранится в .bashrc; практическая польза настройки — визуально различать подключения к разным серверам (например, ярко выделять продакшен), чтобы избежать ошибок из-за перепутанных терминалов.

**Стандарт POSIX**

Синтаксис вызова команд (сначала имя команды, затем ключи/опции, затем аргументы — например, `ls -art --color <шаблон> <путь>`) не является изобретением конкретно Bash или Linux: он закреплён во второй части открытого международного стандарта POSIX и соблюдается разными операционными системами и интерпретаторами.

**Автодополнение по Tab**

Клавиша Tab дополняет вводимые имена команд, файлов, каталогов, переменных и аргументов. Если возможный вариант дополнения не единственный, первое нажатие Tab ничего не выводит, а повторное нажатие показывает список всех подходящих вариантов.

**Встроенные и внешние команды**

Команда `type` показывает, как обрабатывается конкретное имя команды: как встроенная в сам Bash (builtin, например `pwd`, `echo`), как алиас (например, `ls`, если настроен алиас на `ls --color=auto`) или как отдельный бинарный файл, лежащий в файловой системе (например `/usr/bin/find`). Ключ `type -a` показывает все совпадения сразу — например, у `echo` есть и встроенная версия, и отдельный бинарник `/bin/echo` с расширенным набором возможностей; такое дублирование существует, чтобы команда работала даже в шеллах, где встроенного аналога нет.

**Переменная PATH**

Переменная среды PATH хранит список каталогов, где интерпретатор ищет исполняемые файлы команд по имени без указания полного пути. У разных пользователей PATH может отличаться (например, у обычного пользователя может не быть каталога `/usr/local/sbin`, тогда как у root он есть) — это объясняет, почему одна и та же команда доступна одному пользователю и недоступна другому без указания полного пути.

**Алиасы**

Команда `alias` задаёт короткий синоним для длинной команды (удобно для часто повторяющихся многословных вызовов); команда `which` показывает путь к исполняемому файлу команды и ничего не выводит, если файл не найден — это удобный способ проверить наличие программы перед её вызовом в скрипте.

**История команд**

Команда `history` показывает список ранее введённых команд с порядковыми номерами; история сохраняется между сеансами в файле `.bash_history`. Повторный вызов команды из истории возможен через `!<номер>` (по номеру) или `!<начало_имени>` (запускает последнюю подходящую по имени команду); поиск по истории — сочетание Ctrl+R.

**Источники справки**

Иерархия источников справки по командам: неформальные (поиск, LLM-ассистенты), `tldr` (краткие примеры использования команды), встроенная справка `--help`/`-h`, и `man` — наиболее подробный и точный источник, обычно на 99%+ соответствующий реальной версии команды именно на данной платформе (в отличие от ответов LLM, которые могут ориентироваться на другую версию утилиты). В обозначениях справки квадратные скобки `[ ]` — необязательные опции, вертикальная черта `|` — взаимоисключающие варианты, фигурные скобки `{ }` — обязательный выбор одного варианта из списка.

**Работа с man**

`man <команда>` открывает первую подходящую страницу справочника; страницы справочника разбиты по секциям (например, раздел 5 — файлы и их форматы), поэтому `man 5 passwd` открывает описание файла `/etc/passwd`, а `man passwd` без номера — описание команды. Поиск по ключевому слову внутри всех описаний — `man -k <слово>`.

**Осознанное использование LLM в обучении**

LLM-ассистентов стоит использовать как тренера, а не как решателя задач: полезные промпты — просить объяснить команду построчно, назвать подводные камни конструкции, сравнить несколько альтернативных решений задачи, проверить (code review) уже написанный студентом скрипт или сгенерировать набор тренировочных задач возрастающей сложности без готовых решений. Полное делегирование лабораторных работ LLM формирует зависимость и не даёт нарастить «системную сложность» понимания, необходимую для дальнейшего перехода к архитектурному уровню и работе с AI-агентами в разработке.

### Уточнения к текущей лекции

В паре мест лектор допустил неточности или образные упрощения. Отдельно их проговорим.

* **«Самая старая в мире фотография — фотография кота»**: это неточность. Самая старая сохранившаяся фотография в истории — гелиографический снимок Жозефа Нисефора Ньепса «Вид из окна» (около 1826–1827 года), на нём нет кота. Существует отдельный известный факт про одну из самых старых сохранившихся фотографий именно **кота** (около 1870 года), но это не самая старая фотография в мире в целом — лектор объединил два разных факта.
* **Год появления Wayland**: лектор указал 2008 год как момент появления протокола — это соответствует действительности (проект анонсирован Кристианом Хёгсбергом в 2008 году), но первые стабильные релизы и массовое внедрение в дистрибутивах произошли значительно позже (начиная примерно с 2012–2020-х годов), это стоит уточнять при более детальном изучении темы.
* **Инцидент с удалением базы данных GitLab**: описан лектором верно в общих чертах (инженер по ошибке удалил боевые данные, перепутав окружения, в 2017 году), но конкретная деталь про команду `rm -rf /` — образное упрощение; в реальном инциденте была удалена директория с данными PostgreSQL на продакшен-сервере, а не выполнена буквальная очистка корня файловой системы.

### Ключевые понятия

#### Пользовательские интерфейсы Linux

| Термин | Определение для словаря |
| ----- | ----- |
| CLI (Command Line Interface) | Текстовый интерфейс командной строки; основной способ управления Linux, особенно на серверах. |
| TUI (Terminal User Interface) | Приложение, работающее в текстовом режиме, но использующее псевдографику для интерактивного взаимодействия (окна, меню). |
| X11 (X.Org) | Графическая подсистема Linux с клиент-серверной архитектурой, исторически ориентированная на распределённые вычисления; уязвима из-за отсутствия изоляции окон друг от друга. |
| Wayland | Современная графическая подсистема (с 2008 года), обеспечивающая изоляцию окон и более высокую производительность за счёт прямого взаимодействия приложения с ядром и композитором. |
| Композитор (compositor) | Компонент графической подсистемы, отвечающий за отрисовку итогового изображения рабочего стола (перекрытие окон, прозрачность, эффекты). |
| Cockpit | Веб-панель управления отдельным Linux-сервером через браузер (логи, пользователи, сертификаты) без набора команд в терминале. |
| IaC (Infrastructure as Code) | Подход к управлению инфраструктурой через декларативные описания (например, YAML-плейбуки Ansible), обрабатываемые системой автоматизации. |

#### Шелл и командный интерпретатор

| Термин | Определение для словаря |
| ----- | ----- |
| Шелл (shell) | Программа, автоматически запускаемая при входе пользователя в систему и предоставляющая средства работы с ОС; путь к шеллу пользователя указан в /etc/passwd. |
| Bash | Наиболее распространённый командный интерпретатор Linux/Unix-систем; одновременно бинарный файл, командная строка и язык скриптов. |
| Шебанг (shebang) | Специальная конструкция `#!<путь_к_интерпретатору>` в первой строке скрипта, явно указывающая, каким интерпретатором должен выполняться файл. |
| Приглашение ввода (prompt) | Строка вида `user@host:путь$`, сигнализирующая о готовности интерпретатора принимать команды; настраивается через переменную $PS1. |
| POSIX | Международный открытый стандарт, определяющий, среди прочего, единый синтаксис передачи параметров команде (команда → ключи → аргументы). |

#### Приёмы эффективной работы

| Термин | Определение для словаря |
| ----- | ----- |
| Автодополнение (Tab-completion) | Механизм дополнения вводимых имён команд, файлов, каталогов и переменных по клавише Tab; повторное нажатие показывает все варианты. |
| Встроенная команда (builtin) | Команда, логика которой реализована непосредственно внутри бинарника интерпретатора (например, `pwd`, `echo`, `cd`). |
| Внешняя команда | Команда, реализованная как отдельный исполняемый файл в файловой системе (например, `/usr/bin/find`). |
| type | Команда, показывающая, как обрабатывается конкретное имя: как builtin, алиас или путь к внешнему бинарнику. |
| which | Команда, выводящая путь к исполняемому файлу программы; ничего не выводит, если файл не найден — удобно для проверки наличия программы. |
| alias | Команда для создания короткого синонима длинной команды или последовательности ключей. |
| PATH | Переменная среды со списком каталогов, где интерпретатор ищет исполняемые файлы по имени без указания полного пути. |
| history | Команда вывода истории введённых команд с номерами; история сохраняется между сеансами в файле .bash_history. |

#### Справка

| Термин | Определение для словаря |
| ----- | ----- |
| tldr | Утилита краткой справки, показывающая типовые примеры использования команды без подробного описания всех ключей. |
| man (manual pages) | Наиболее подробный и точный источник встроенной справки, разбитый на тематические секции (команды, системные вызовы, файлы и форматы и др.). |
| man -k | Режим поиска по ключевому слову среди описаний всех страниц справочника. |
| Квадратные скобки [ ] в синтаксисе справки | Обозначение необязательной опции или параметра команды. |
| Фигурные скобки { } в синтаксисе справки | Обозначение обязательного выбора одного варианта из перечисленных. |
