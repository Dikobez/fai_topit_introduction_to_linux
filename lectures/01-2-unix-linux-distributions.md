## Конспект

**От Unix к Linux: почему история важна**

Прежде чем говорить о Linux, необходимо понять историю Unix — идеологического предка всех современных Unix-подобных систем. Знание истории технологии даёт инженерный опыт (типовые решения повторяются) и позволяет понимать вектор развития отрасли, а не только текущий срез.

**Рождение Unix: Bell Labs, Ритчи и Томпсон**

Unix создали Кен Томпсон и Деннис Ритчи, сотрудники Bell Labs, работавшие на компьютере PDP. Изначально система создавалась как побочный проект (по легенде — чтобы иметь возможность запускать любимую игру), а в 1971 году для PDP-11 Unix был полностью переписан на языке Си, который для этого разработал сам Ритчи. Кроме Unix и языка Си, дуэт внёс значительный вклад в информатику в целом, за что их можно сравнить с многопрофильными учёными прошлого.

**Ветви развития Unix: System V и BSD**

От оригинального Unix исторически разошлись две ветви: System V (SysV) — «настоящий» коммерческий Unix, который до сих пор используется на мейнфреймах и суперкомпьютерах IBM и Hewlett-Packard, и BSD (Berkeley Software Distribution) — открытая ветвь, давшая жизнь таким системам, как FreeBSD и OpenBSD. Обе ветви унаследовали идеологию оригинального Unix, но развивались независимо.

**Идеология Unix: главные принципы**

Ритчи и Томпсон построили систему вокруг минимального набора сущностей — по большому счёту это процесс и файл. Из этого выросли два ключевых принципа: «в Unix всё есть файл» (устройство, процесс, канал — всё представлено файлом, что унифицирует доступ через стандартные операции чтения/записи без специальных системных вызовов) и Unix way — «одна программа, одна функция», при котором сложные задачи решаются комбинированием простых узкоспециализированных утилит (например, через конвейеры/пайпы). Классический Unix также стремился к минимальному ядру, выводя максимум функциональности за пределы kernel space, — то есть тяготел к микроядерной архитектуре, а также закладывал максимальное абстрагирование от оборудования для переносимости системы.

**Проект GNU и Ричард Столлман**

GNU (рекурсивный акроним «GNU's Not Unix») — проект, основанный Ричардом Столлманом, одним из идеологов движения свободного программного обеспечения (open source). Помимо идеологии и деклараций, проект дал набор системных утилит (GNU coreutils), текстовый редактор Emacs и попытку собственного ядра (полноценно не заработавшего). Без поддержки и популяризации проекта GNU ядро Linux не получило бы такой доли рынка — исторически Unix и BSD появились раньше Linux, но подобной популярности не добились.

**Линус Торвальдс и рождение Linux**

В 1988 году студент Линус Торвальдс с другом Ларсом Веандером учились на инженеров и работали на университетском компьютере с системой Ultrix (ещё один Unix-подобный вариант). В 1990 году Торвальдс купил свой первый компьютер на процессоре 386 с системой Minix (учебный минималистичный Unix) и, желая удобнее работать в Usenet (прото-интернет-форумах), начал писать собственный терминал, затем драйвер клавиатуры — и не смог остановиться. 25 августа 1991 года он опубликовал сообщение о нулевой версии своего ядра с предложением всем желающим его протестировать, добавив, что не рассчитывает на большую популярность проекта; уже в сентябре 1991 года вышла версия 0.11 с предложением присоединиться к разработке.

**Происхождение названия Linux**

Проект изначально назывался Torvalds "Freax" (сочетание "free", "freak" и "x" как намёк на Unix) — это слово до сих пор встречается в ранних исходниках ядра. Название "Linux" появилось случайно: один из коллег Торвальдса, размещая файлы на FTP-сервере, назвал каталог по имени автора — Linus, и оно закрепилось. В 1994 году вышла первая версия под лицензией GNU, что окончательно определило юридический статус проекта как открытого. Логотип-пингвин Tux был нарисован Ларри Юингом в 1996 году, то есть уже спустя годы после появления самого ядра.

**Linux — это ядро, а не операционная система**

Распространённое заблуждение — считать Linux полноценной операционной системой. Формально Linux — это только ядро: модульный монолит, который решает задачи абстрагирования оборудования и разделения ресурсов, но не включает пользовательский интерфейс, командную оболочку, драйверы прикладного уровня и систему управления пакетами — это область дистрибутивов. Убедиться в этом можно командой uname (например, uname -a), которая показывает версию именно ядра, а не операционной системы в целом.

**Как устроена разработка ядра**

Разработкой руководит фонд Linux Foundation, во главе которого стоит Линус Торвальдс. Структура ролей: мейнтейнеры отвечают за конкретные модули и проверяют вносимые изменения, а над ними — ответственные за релиз конкретной версии ядра. Изменения поступают от энтузиастов-одиночек и от компаний (Google, Red Hat и др.), которые заинтересованы в развитии Linux как платформы для своих продуктов; модель управления называют «меритократической демократией» — все участвуют на равных, но финальные архитектурные решения принимает ограниченный круг лиц. Из-за монолитной архитектуры ядра требования к качеству кода крайне высоки (падение одного немодульного компонента может обрушить всю систему), поэтому используется многоуровневое тестирование и система контроля версий Git; финансирование обеспечивают как частные пожертвования, так и крупные корпоративные спонсоры.

**Версионирование ядра**

Версия ядра состоит из трёх чисел: мажорный релиз (значимые изменения, выходит раз в несколько лет — сейчас актуально 7-е поколение), минорный релиз (новая функциональность без существенных алгоритмических изменений, выходит примерно раз в 9–10 недель) и патч (исправление ошибок без новых функций). Поддержка версий ядра частично перекрывается по времени, чтобы у пользователей было время безопасно перейти на новую версию, не переключаясь мгновенно.

**Дистрибутив: ядро + экосистема**

Дистрибутив — это ядро Linux плюс набор пакетов, конфигурация и модель обновлений, то есть готовая для пользователя экосистема вокруг открытого ядра. Любой желающий может взять ядро, собрать вокруг него бинарные пакеты, подготовить пользовательское окружение и инсталлятор — так появляется огромное разнообразие дистрибутивов (Debian, Ubuntu, Fedora, Arch, Astra Linux и другие).

**Модели релизов дистрибутивов**

| Модель релизов | Особенности | Для кого подходит | Примеры |
| :---- | :---- | :---- | :---- |
| Fixed release (фиксированные релизы) | Новые версии выходят раз в 1–1.5 года; во время поддержки — только патчи безопасности и исправления ошибок, без драматических архитектурных изменений | Enterprise, где важна предсказуемость | Debian, Ubuntu (и производные) |
| LTS (Long Time Support) | Подвид фиксированных релизов с увеличенным сроком поддержки конкретного поколения | Корпоративная инфраструктура с плавным переходом между версиями | Ubuntu LTS |
| Rolling release (непрерывные релизы) | Обновления, в том числе мажорные, поступают постоянно | «Полигон» для отладки новых технологий перед выпуском в стабильный enterprise-дистрибутив | CentOS (ранее), Fedora, Arch |

Пример связки: компания Red Hat продаёт коммерческий RHEL (Red Hat Enterprise Linux) с поддержкой, а новые технологии предварительно «обкатывает» на открытых rolling-дистрибутивах (историческая роль CentOS, современная — Fedora) прежде чем переносить их в стабильный enterprise-продукт.

**Зачем обновлять дистрибутив**

Обновления нужны не только для безопасности: они приносят улучшения производительности (например, переход системы инициализации от init к systemd на CentOS 6→7 существенно ускорил загрузку) и поддержку нового оборудования — старые версии ядра постепенно теряют драйверы устаревших устройств, которые физически исчезают с рынка (например, недавно из свежих версий ядра были удалены драйверы старых чипсетов Adaptec).

**Форматы пакетов и репозитории**

Дистрибутивы делятся на две большие семьи по формату бинарных пакетов: RPM-семейство (Red Hat, CentOS, Fedora, Astra Linux, РЕД ОС) и APT/DEB-семейство, происходящее от Debian (Ubuntu, Linux Mint, Astra Linux — на базе Debian). Репозиторий — это своего рода «магазин приложений» для дистрибутива (аналог App Store/Google Play), из которого менеджер пакетов скачивает и устанавливает нужное программное обеспечение вместе со всеми зависимостями; после установки могут запускаться триггеры — сценарии, выполняющие дополнительные настроечные действия.

**Конфигурационные файлы**

Конфигурационный файл — это обычный текстовый файл с параметрами настройки системы (например, /etc/resolv.conf задаёт адрес DNS-сервера, /etc/hostname — имя компьютера). Разные семейства дистрибутивов (RPM vs Debian-based) по-разному организуют такие файлы, что усложняет перенос конфигураций между дистрибутивами, хотя унификация через systemd частично сгладила эти различия.

**Другие критерии различия дистрибутивов**

Дистрибутивы также отличаются графическим окружением (GUI, необязательный компонент — на серверах его обычно не устанавливают), тюнингом ядра под конкретную задачу (встраиваемые системы, роутеры с урезанным набором модулей, системы реального времени для станков с ЧПУ и АЭС) и общей философией — от «дружелюбных» новичкам систем (Ubuntu, Linux Mint) до систем с гибкой настройкой и подробной документацией (Arch Linux и его знаменитая ArchWiki).

**Практическая демонстрация: uname и работа с ядром**

На примере среды WSL2 (Windows Subsystem for Linux) показано, что Microsoft адаптировал ядро Linux специально для работы внутри Windows; команда uname -r показывает версию именно ядра (например, 6.6.x), а определить конкретный дистрибутив (в примере — Debian 13 "Trixie") можно через файл /etc/os-release. Само ядро физически хранится в виде файла в файловой системе и инициируется при старте системы; при обновлении в системе может остаться сразу несколько версий ядра для возможности откатиться при проблемах.

**Работа с пакетами и терминалом**

Установка программ через APT происходит командой вида apt install <имя_пакета> — менеджер пакетов обращается к репозиторию, скачивает нужный пакет и все его зависимости. Полезный навык работы в терминале — автодополнение по клавише Tab: одно нажатие дополняет команду или путь до однозначного варианта, двойное нажатие показывает список всех возможных вариантов, что критично для эффективной и безошибочной работы с длинными путями файлов.

**Виртуальные терминалы (TTY)**

Linux поддерживает несколько независимых текстовых консолей (виртуальных терминалов), переключаемых комбинациями вида Alt+F1…Alt+F4 (в системах с графическим окружением графический стол обычно занимает одну из следующих консолей). Это удобно для параллельной работы: в одной консоли можно писать код, в другой — тестировать, в третьей — смотреть логи.

### Исправления

В ходе лекции преподаватель уточнил несколько распространённых заблуждений — стоит зафиксировать их отдельно, чтобы не закрепить неверные формулировки в собственных заметках.

* **«Linux — это операционная система»** — это неверно в строгом смысле. Linux — это только ядро; полноценная ОС (с интерфейсом, командной оболочкой, менеджером пакетов и т. д.) формируется дистрибутивом вокруг этого ядра.
* **Название проекта Торвальдса** изначально было не «Linux», а «Freax» — имя «Linux» возникло случайно, когда коллега назвал папку с файлами на FTP-сервере по имени автора.
* **Классический Unix стремился к микроядру**, а не к монолиту — это важно не путать с Linux, который на практике реализован как модульный монолит, несмотря на общее идеологическое наследие Unix.
* **Компьютер, на котором работали Ритчи и Томпсон**, в лекции упоминается как модель линейки PDP (в частности, PDP-11, для которой в 1971 году Unix переписали на Си) — стоит различать эту платформу от учебных Ultrix/Minix, с которыми позже работал Торвальдс: это разные Unix-подобные системы разных эпох.
* **Логотип-пингвин Tux** появился не одновременно с ядром, а лишь в 1996 году — спустя пять лет после первого релиза Linux.

### Персоналии

* **Кен Томпсон** — сотрудник Bell Labs, соавтор Unix.
* **Деннис Ритчи** — сотрудник Bell Labs, соавтор Unix и автор языка программирования Си, на котором Unix был переписан в 1971 году.
* **Ричард Столлман** — идеолог движения свободного программного обеспечения (open source), основатель проекта GNU.
* **Линус Торвальдс** — создатель ядра Linux (первый релиз в 1991 году), сегодня возглавляет разработку ядра в рамках Linux Foundation.

### Ключевые понятия

#### Идеология Unix

| Термин | Определение для словаря |
| ----- | ----- |
| Unix | Идеологический предок Linux и всех современных Unix-подобных систем; операционная система, задавшая базовые принципы построения ОС этого семейства. |
| Unix way | Идеологический принцип «одна программа — одна функция»: сложные задачи решаются комбинацией простых специализированных утилит (например, через конвейеры). |
| «Всё есть файл» | Принцип Unix/Linux, согласно которому устройства, процессы и другие сущности представляются файлами, что унифицирует способ доступа к ним. |
| Микроядерная архитектура (в контексте Unix) | Идеологическая цель классического Unix — минимальное ядро с максимумом функциональности за пределами kernel space (в противовес монолиту). |

#### Роль GNU

| Термин | Определение для словаря |
| ----- | ----- |
| GNU | Рекурсивный акроним "GNU's Not Unix"; проект свободного программного обеспечения, давший в том числе набор системных утилит (coreutils) и редактор Emacs; без его поддержки и популяризации ядро Linux не получило бы текущей доли рынка. |
| Open source / свободное ПО | Модель распространения программного обеспечения с открытыми исходными кодами, часто бесплатная, но с определёнными лицензионными ограничениями. |

#### Linux как ядро

| Термин | Определение для словаря |
| ----- | ----- |
| Linux (ядро) | Модульный монолит — только ядро операционной системы, решающее задачи абстрагирования оборудования и разделения ресурсов; не включает интерфейс, оболочку и менеджер пакетов. |
| Linux Foundation | Организация, координирующая и финансирующая разработку ядра Linux. |
| Мейнтейнер (maintainer) | Разработчик, отвечающий за конкретный модуль ядра и проверяющий вносимые в него изменения. |
| Мажорная/минорная версия/патч | Три уровня номера версии ядра: мажорный релиз — значимые изменения; минорный — новая функциональность без коренных изменений; патч — исправления ошибок. |
| uname | Команда для получения информации о системе, в том числе версии ядра (например, uname -a, uname -r). |

#### Понятие дистрибутива

| Термин | Определение для словаря |
| ----- | ----- |
| Дистрибутив | Ядро Linux плюс набор пакетов, конфигурация и модель обновлений — готовая для пользователя экосистема. |
| Fixed release | Модель релизов с фиксированными версиями и стабильностью на протяжении цикла поддержки; предпочтительна для enterprise. |
| LTS (Long Time Support) | Дистрибутив/версия с увеличенным сроком поддержки, удобная для корпоративной инфраструктуры. |
| Rolling release | Модель релизов с постоянными, в том числе мажорными, обновлениями. |
| RPM | Формат бинарных пакетов, используемый в семействе дистрибутивов Red Hat (RHEL, CentOS, Fedora и др.). |
| APT/DEB | Формат бинарных пакетов и менеджер, используемый в семействе дистрибутивов Debian (Ubuntu, Mint и др.). |
| Репозиторий | Онлайн-хранилище пакетов программного обеспечения для дистрибутива, аналог магазина приложений. |
| Конфигурационный файл | Текстовый файл с параметрами настройки системы или программы (например, /etc/resolv.conf, /etc/hostname). |
| WSL2 (Windows Subsystem for Linux) | Технология Microsoft, позволяющая запускать адаптированное ядро Linux и linux-приложения внутри Windows. |
| Виртуальный терминал (TTY) | Независимая текстовая консоль в Linux, между которыми можно переключаться сочетаниями клавиш (например, Alt+F1…F4). |
