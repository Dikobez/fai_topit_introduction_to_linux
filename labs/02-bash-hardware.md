### Цель работы:

Расширить практику программирования на bash за счёт доработки скрипта инвентаризации из Практической работы №1; освоить утилиты работы с оборудованием и модулями ядра Linux; закрепить понимание установки ПО через менеджера пакетов apt и практическое понимание устройства ядра (версия, расположение файлов модулей, загружаемые и неудаляемые модули).

### Необходимо:

- Права root или sudo для установки пакетов и работы с модулями ядра

### Краткие теоретические сведения

Скрипт и командный интерпретатор

Скрипт — текстовый файл с командами, который выполняется бинарным файлом командного интерпретатора без предварительной компиляции. Один из самых распространённых интерпретаторов для UNIX-подобных систем — bash (Bourne-Again SHell, «переродившийся» аналог старого shell sh). В Linux bash обычно расположен по пути /bin/bash и является шеллом по умолчанию. Он умеет запускать как внешние бинарные команды, так и встроенные в себя (builtin); понять, чем на деле является конкретная команда (внешней программой, встроенной командой или алиасом), помогает утилита type.

Переменные и вычисления в bash

В bash все переменные по типу — строки; то, что значение является числом, интерпретатор определяет по контексту использования. Переменная объявляется как VAR="значение" (без пробелов вокруг "="), а обращение к ней — через $VAR или ${VAR}. Вторая форма нужна, когда переменную требуется явно «отделить» от окружающих символов либо когда используются расширенные конструкции, например ${VAR:-значение_по_умолчанию}. Результат выполнения команды можно сохранить в переменную через $(команда). Целочисленная арифметика оформляется конструкцией $(( выражение )); операции с плавающей точкой (например, деление с заданной точностью) выполняются внешней утилитой bc, так как сам bash считает только целые числа.

Управляющие конструкции

В bash есть условный оператор if с операторами сравнения целых чисел (-eq, -ne, -lt, -le, -gt, -ge), оператор множественного выбора case, циклы for (в том числе по диапазону, генерируемому утилитой seq) и while, а также команды break и continue для управления ходом цикла. Ввод данных от пользователя в переменную выполняется командой read. Повторяющуюся логику можно оформить в виде функции, а параметры функции доступны внутри неё как $1, $2 и так далее.

Драйверы устройств и модули ядра

Для работы с любым оборудованием, кроме процессора и памяти (ими управляет само ядро напрямую), требуется драйвер — программный компонент, предоставляющий унифицированный программный интерфейс доступа к устройству и абстрагирующий его от вышележащего программного слоя. Драйвер всегда специфичен и для конкретного устройства, и для конкретной операционной системы.

Ядро Linux формально монолитное — все драйверы и подсистемы работают в едином адресном пространстве ядра, отделённом от пользовательского пространства. Но в отличие от «чистого» монолита, модули ядра Linux можно загружать и выгружать динамически, без пересборки и перезагрузки ядра. При подключении оборудования это чаще всего происходит автоматически: событие обрабатывает демон udev, который создаёт файл устройства в каталоге /dev. Сами файлы модулей (.ko) хранятся в каталоге /lib/modules/<версия_ядра>/kernel/drivers/<тип_устройства>. Если производитель не раскрывает интерфейс устройства, требуется закрытая микропрограмма — firmware, которая хранится в файлах .bin в каталоге /lib/firmware.

Версию ядра и общие сведения о системе показывает утилита uname. Для работы с модулями служат lsmod (что загружено), modinfo (сведения о модуле), modprobe и insmod (загрузка модуля — modprobe умеет автоматически подгружать зависимости, insmod нет), rmmod (выгрузка). Модуль нельзя выгрузить, если от него зависят другие загруженные модули — сначала нужно выгрузить их. Для автозагрузки модуля при старте системы создаётся файл .conf в каталоге /etc/modules-load.d с именем модуля внутри; чтобы запретить автозагрузку — файл с директивой blacklist <имя_модуля> в каталоге /etc/modprobe.d.

Инвентаризация оборудования

Информацию о работающем оборудовании дают утилиты lsusb (устройства на шине USB), lspci (устройства на шине PCI), lshw (наиболее подробный отчёт, поддерживает несколько форматов вывода) и dmidecode (данные из таблиц SMBIOS/DMI — модель материнской платы, BIOS и т.п.). Сведения о процессоре и памяти можно получить из файлов виртуальной файловой системы /proc/cpuinfo и /proc/meminfo либо командами lscpu и lsmem.

Установка ПО через apt

Если нужной утилиты нет в системе, её устанавливают через менеджер пакетов apt, который скачивает пакет из подключённого репозитория, например apt install pciutils устанавливает пакет, содержащий lspci. Полезно заранее понимать, из какого пакета берётся нужная команда — это можно уточнить в документации дистрибутива или поиском по названию утилиты используя команду apt search, например так apt search lspci.

Справка и работа с текстовым выводом

Подробную справку по команде даёт man (например, man lsusb), краткую — ключ -h/--help. Команды apropos и whatis помогают найти нужную man-страницу по описанию. Справка по конфигурационным файлам находится в 5-й секции man, например man 5 modules-load.d. Если вывод команды слишком длинный, его удобно передать через конвейер (|) в less для постраничного просмотра (выход — клавиша q) или в sort для сортировки, например lsmod | sort | less.

Права на выполнение скрипта

Скрипт — обычный текстовый файл; чтобы запускать его напрямую по имени (а не передавать явно в интерпретатор), пользователю-владельцу нужно назначить право на выполнение командой chmod.

- Прочие утилиты: tail, head, cat, sort

#### Часть 3. Скрипт расчёта производительности в FLOPS

Разработайте скрипт с именем script23, который оценивает производительность CPU в FLOPS (Floating Point Operations Per Second) — количестве операций с плавающей запятой в секунду. Это применяется для оценки вычислительной мощности, когда важны сложные математические операции с высокой точностью.

1. Создайте скрипт, который выполняет достаточно большое количество (не менее сотни) операций умножения двух одинаковых нецелых чисел с точностью 10 знаков после запятой, замеряет затраченное время в секундах и вычисляет значение FLOPS.

2. Для расчётов используйте bc, но так, чтобы при вычислениях ничего не выводилось на консоль. Вычисление оформите в виде функции; время фиксируйте в переменные до и после вызова функции.

Примечание:

- Для замера времени используйте команду date с ключом +%s%N (секунды и наносекунды) или встроенную переменную $SECONDS — не пытайтесь считать время «на глаз».

- Подавить вывод bc внутри функции можно перенаправлением в /dev/null; сам результат вычисления получайте отдельным вызовом bc через command substitution $( ).

- Не забывайте, что деление в целочисленной арифметике bash даёт округление — для расчёта итогового FLOPS (операции / время) тоже используйте bc, а не $(( )).

Чек-лист для части 3:

- Скрипт script23 выполняет не менее 100 операций умножения нецелых чисел с точностью 10 знаков.

- Вычисления оформлены как функция, вызовы которой не выводят промежуточных значений на экран.

- Замер времени сделан до и после вызова функции, итоговое значение FLOPS вычислено и выведено пользователю.

- Вы можете объяснить, почему это упрощённая оценка производительности (пригодится для отчёта).

Примечания:

### Содержание отчёта

Требуется подготовить отчёт в формате MD или PDF. Отчёт содержит титульный лист, артефакты выполнения и ответы на вопросы и задания.

Артефакты:

1. Строка alias и содержимое $PS1 из Части 1.

2. Все скрипты из Частей 2 и 3 (script221–script226, script23).

3. Доработанный скрипт инвентаризации и сгенерированный им отчёт из Части 4.

4. Конфигурационный файл blacklist из Части 5.

Вопросы и задания:

1. Как определить, сколько параметров пользователь передал в скрипт при запуске?

2. Какие недостатки есть у вашего подхода к определению производительности в FLOPS?

3. В нашем скрипте инвентаризации мы ради архитектурной чистоты не используем концепцию UNIX-way, которая ориентирована на разработку длинных конвейеров команд. Как можно в конвейере реализовать сразу сбор данных о CPU без промежуточных файлов? Напишите по одному аргументу за и против обоих подходов.

4. Утилиты modprobe и insmod нужны для загрузки модулей. В чём между ними разница?

5. Предположим, вам необходимо, чтобы в системе использовалась аппаратная реализация алгоритма шифрования AES на CPU. Как определить, поддерживает ли процессор эту функцию?

6. В Части 5 п.6 вы загрузили модуль драйвера. Откуда команда modprobe «узнала», где расположен файл этого модуля?

7. В каких форматах утилита lshw может генерировать отчёты? Для чего могут использоваться отчёты в каждом из форматов?

8. Опишите значение полей в выводе команды lsmod.

### Понятийный минимум по работе

1. Переменная окружения и переменная шелла; конструкция ${VAR:-значение}

2. Арифметическое расширение $(( )) и подстановка результата команды $( )

3. Условные операторы if/case и циклы for/while в bash

4. Драйвер устройства и его роль абстрагирования оборудования

5. Модуль ядра (.ko), его загрузка и выгрузка без перезагрузки ядра

6. Демон udev и автоматическое создание файлов устройств в /dev

7. Firmware (закрытая микропрограмма устройства) и её отличие от драйвера

8. Автозагрузка и блокировка модулей (/etc/modules-load.d, /etc/modprobe.d, blacklist)

9. Менеджер пакетов apt и установка ПО из репозитория

10. Утилиты инвентаризации оборудования: lscpu, lsusb, lspci, lshw, dmidecode
