## Краткие теоретические сведения:

VirtualBox

Система виртуализации VirtualBox предназначена для запуска нескольких операционных систем на одном компьютере. Основная операционная система. Называется родительской. Операционные системы, запускаемые внутри среды, виртуализации гостевыми операционными системами, или (что не совсем корректно) виртуальными машинами. Для управления ими может использоваться графическая оболочка VirtualBox. Или утилиты командной строки. А в свойствах виртуальной машины мы можем изменять или настраивать параметры ее оборудования, параметров эмуляции сети. Некоторые параметры могут быть изменены на «ходу», некоторые доступны только при выключенной гостевой операционной системе. Также важным инструментом является создание снимков виртуальной машины – «слепков» ее текущего состояния, к которым можно вернуться в любой момент.

Linux

Linux – UNIX-подобная, многозадачная операционная система. Основным для нее является текстовый интерфейс командной строки (терминал), хотя для Linux разработаны (или портированы) графические оболочки, такие как KDE или Gnome.

Справку по каждой команде можно получить прямо в терминале с помощью команды man, а краткую с помощью ключа –h (--help). Например:

```bash
man ps
```

```bash
ps –help
```

Также полезными для получения справки могут оказаться команды whatis.

Основные приемы работы в терминале

Основным приемом работы является использование команд или утилит командной строки прямо в терминале.

Терминал — интерфейс ввода-вывода команд для shell. В Linux бывает двух видов: tty — виртуальная консоль, обслуживаемая ядром напрямую (таких терминалов создается несколько, для переключения между ними используется комбинация Alt+F1 для первого терминала, Alt+F2 для второго и т.д.)  и pty — псевдотерминал, создаваемый программой: эмулятором терминала в GUI, SSH-клиентом или tmux/screen. Проверить, к какому терминалу подключена ваша сессия, можно командой tty.

Пользователь набирает команды в терминале и видит результат их выполнения.

Полезные приёмы:

стрелки вверх и вниз на клавиатуре позволяют «листать» ранее введенные команды и возвращаться к ним (не нужно вводить их заново).

Для работы с историей команд используется специальная команда history. О ней идет речь в этой практике.

В командной строке работает автодополнение команд и путей в файловой системе по клавише Tab. Если набрать начало команды или пути к файлу и нажать Tab – система сама подставит продолжение.

Команды могу объединяться для последовательного выполнения в конвейеры специальными символами, например “|”.

Скрипты

Команды могут объединяться в Shell-скрипт – это обычный текстовый файл, в который последовательно записаны команды, которые пользователь может обычно вводить в командной строке. Файл выполняется командным интерпретатором – шеллом (shell). В Linux- и Unix-системах для того, чтобы бинарный файл или скрипт смогли быть запущены на выполнение, для пользователя, который запускает файл, должны быть установлены соответствующие права на выполнение (подробно с этим мы разберемся в отдельной практической работе). Назначить право пользователю на выполнение скрипта можно с помощью команды

```bash
chmod u+x имя_скрипта или chmod 700 имя_скрипта
```

Рассмотрим пример (рис.3):

[Рис. 3](images/01-fig-03.png)

Команда date выводит текущую дату. Затем мы записываем строку date в файл script1. Затем мы пытаемся запустить файл на выполнение. Обратите внимание, что в общем случае нужно указывать полный путь от корня (самого «верха») файловой системы для файла. Например /home/username/scriptname, но в данном примере путь к файлу начинается с “./”, а точка означает текущий каталог, т.е. мы находимся именно в нем и скрипт находится в этом каталоге.

Запустив файл script1 сразу после создания, мы получаем сообщение о недостаточности прав для запуска.

Скрипт, однако можно запустить, передав его в качестве аргумента в командный интерпретатор (см. следующую строку на рис.3). Если мы хотим, чтобы скрипт запускался сам, по имени, то с помощью команды chmod назначаем нужные права. Дальше скрипт может быть запущен самостоятельно.

Для создания скрипта можно воспользоваться текстовым редактором nano или vi, набрав имя редактора в командной строке.

В скриптах можно делать комментарий, например строки, начинающиеся с символа # (за исключением комбинации #!), являются комментариями. Комментарии могут также располагаться и в конце строки с исполняемым кодом.

Заметим еще раз, что скрипты запускаются с указанием полного пути от корня файловой системы, например:

```bash
/home/myname/superscript.sh
```

или, если скрипт в текущем каталоге, то:

```bash
./superscript.sh
```

Установка программного обеспечения

Для установки программного обеспечения чаще всего используют менеджеры пакетов. Менеджер пакетов подключается к репозитарию и скачивает из него программы или их исходный код. В Debian используется менеджер пакетов apt. Установка ПО выглядит так:

```bash
apt install имя_пакета
```

Это типичная задача системного инженера перед передачей сервера коллегам. При разработке скрипта следует сразу разбить задачу на отдельные этапы, как это принято в нормальных архитектурных практиках. Скрипт будет работать по шагам:

Шаг 1 - сбор сырых данных,

Шаг 2 - обработка данных, формирование отчета,

Шаг 3 - логирование работы скрипта.

В следующих практических работах мы будем дорабатывать этот скрипт.

Скрипт должен:

Создать каталог PASSPORT (и подкаталоги PASSPORT/log и PASSPORT/tmp), используя mkdir -p, чтобы повторный запуск не вызывал ошибок.

Собрать в каталоге PASSPORT/tmp отдельные файлы с расширением tmp, содержащие дату формирования и имя хоста; имя пользователя, выполняющего скрипт (whoami, who); текущий каталог и список файлов в нём (pwd, ls).

Сформировать файл PASSPORT/passport.txt со структурированным отчётом, где каждый раздел подписан заголовком (например, "=== Информация о хосте ==="). Данные следует брать из временных файлов.

Дописать в файл PASSPORT/log/report.log строку вида "Скрипт был запущен: <дата-время>" при каждом запуске, не стирая предыдущие записи (используйте >> и конструкцию $(date) для вставки текущей даты в строку).

В конце скрипта найти и удалить все .tmp-файлы в PASSPORT и его подкаталогах одной командой через find.

Сделайте этот файл исполняемым. Проверьте работу скрипта (если не уверены, сделайте снимок виртуальной машины).

Примечание: понятно, что для решения этой задачи такое структурирование не является необходимым, но хорошие архитектурные практики лучше осваивать на простых примерах.
